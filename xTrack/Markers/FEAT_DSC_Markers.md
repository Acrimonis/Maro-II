# Feature: Markers

**Description:**
User-defined markers on the map — Pin, Circle, and Corridor geometries. Line-of-sight matching with proximity-zone pre-filter (land-blocking via coastline spatial index + 10m grazing tolerance). On-demand "where am I?" query via boat marker tap. Step-by-step wizard for creation/editing. Viewing drawer (card layout) + match result display. Management page with swipe-to-delete. OSMdroid native overlays. Binary layer toggle (HIDDEN/SHOW_ALL). POI emoji icons on markers; pin is a real persisted flag.

## Rules

- A corridor's containment is a rounded pill: a boat within `widthM / 2` of either endpoint is inside, even when its perpendicular projection falls past the segment end.
- An auto 🕐 idle marker's proximity range is `AppConfig.boatMarkerAutoMarkerProximityM` (`track.boatMarker.autoMarker.proximityM`, 300 m default), so where-am-i matches it only within that range.
- A marker's icon is a pure POI emoji with no pin semantics; pin is the persisted `UserMarker.pinned` boolean mirroring tracks, and the marker layer stays binary HIDDEN / SHOW_ALL.
- The marker filter's `icon` axis reads WITH_ICON / WITHOUT_ICON and its `pinned` axis reads All / Pinned / Unpinned.
- Diving-tier auto-naming keys on `icon == 🤿`, never on `pinned`.
- Pinned and unpinned markers are told apart by the halo ring alone — pin dimming is removed — while search dimming stays.
- The halo is a static ring (no animation) drawn around the marker's centre dot or its emoji at an absolute radius, and never on an unconfirmed marker.
- The selected marker's gold is driven by `selectedMarkerId` alone, which also forces that marker's zones visible.
- A selected marker is drawn as a dark under-stroke beneath its gold, so the outline reads on any background.
- A highlighted track is drawn as a dark under-stroke beneath a gold core, so the outline reads on any background.
- A marker's dashboard-open fit frames its extent to a stated share of the smaller displayed map dimension — corridor `marker.focus.corridorShare`, circle and pin `marker.focus.zoneShare` — centred on `UserMarker.centerPoint`.
- The framed extent is the body plus the proximity collar, read through the reach's one home `markerProximityRangeM`; the pin's zoom-in-only lock is dropped, with `marker.focus.pinFootprintM` as its floor.
- The marker tile's header leads with its icon-picker action, its box the glyph's width (24×36 dp), and the coordinate text's only start gap is `MARKER_HEADER_ICON_GAP` (2 dp).
- The marker filter's routing criteria are two independent axes — `routeCost` and `routeRole` — ANDed, because a single-select panel cannot hold a cost and a role at once.
- A marker's two route roles — `routeOrigin` and `routeDestination` — are independent booleans, either, both or neither, additive with no migration.
- The routing cost's bound has one home: `ROUTING_COST_MAX = 9` prices the marker and `ROUTING_COST_BLOCKED = 10` walls it, with `validRoutingCost` accepting `1..10`.
- Both markers headers head their action group with one shared create action, divided from the read-chrome group by a vertical rule and ordered `create · rule · chrome group`; the action owns its own rule and its content description.
- The menu's create action sits outside the `markerFilterAxes` gate, so creation never disappears with the filters.
- A marker flagged `routingOnly` is a routing weight alone: the where-am-i lookup excludes it before any match resolves, and it never names a track or route.
- A routing-only marker dashes every ring and hatches every fill it draws, while the corridor's always-on centre line stays solid.
- The markers backup takes every marker with `origin == USER || trackId == null`, and Export all takes every marker held.
- An imported marker's identity is the payload blob's `id`, else the mirror's, else the waypoint name (first-wins), and a foreign waypoint is born a keeper Pin, never an auto marker.
- A single-file marker import asks Duplicate / Override / Cancel on a match; a ZIP import never asks and always skips.
- The marker filter's three routing axes — route role, routing cost and routing-only — stand under one `Routing` title in the order role · cost · Only, each keeping its own card.
- Two adjacent filter axes carrying the same `labelResId` render under one shared title: `FilterControl` emits a `PopupSectionTitle` only when the axis's key differs from the one drawn last.
- The wizard's Radius/Width and Proximity steps use the shared `ScaledSliderRow`: an off-by-default ×10 checkbox opening 0–250 m or 0–2500 m, a value above the ceiling clamping when the toggle is switched off.
- The marker creation wizard replaces the dashboard while creating or editing, each step presenting one decision, with the map left visible and draggable during a position step.
- The wizard's steps are separate composables under `markers/wizard/steps/`.
