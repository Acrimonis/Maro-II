## Data Model

### Sealed Geometry Hierarchy
**Decision:** `MarkerGeometry` sealed class with three variants: `Pin(position)`, `Circle(center, radiusM)`, `Corridor(p1, p2, widthM)`.
**Rationale:** Exhaustive `when` matching, no default branch, compiler-enforced completeness.
**Source:** [`UserMarker.kt`](app/src/main/java/ykws/android/maro/data/model/markers/UserMarker.kt)

### Proximity Override Per Marker
**Decision:** `proximityOverrideM: Double?` on UserMarker. Null → use default formula (pin=200m, circle=radius×3, corridor=width×3). Non-null → exact value.
**Rationale:** User-configurable per-marker alert distance without changing global defaults.
**Source:** [`UserMarker.kt`](app/src/main/java/ykws/android/maro/data/model/markers/UserMarker.kt:29), [`MarkersViewModel.kt:504-508`](app/src/main/java/ykws/android/maro/ui/map/MarkersViewModel.kt:504)

### BBox Pre-Filter
**Decision:** Every UserMarker has a pre-computed axis-aligned bounding box (`bbox`). `resolveAllMarkers()` gates on cheap BBox overlap before expensive land-blocking.
**Rationale:** 15K coastline edges × 20 markers = 300K edge tests → BBox reduces to 1-3 markers within 1km search fence.
**Source:** [`MarkerMatcher.kt`](app/src/main/java/ykws/android/maro/spatial/MarkerMatcher.kt)

### Icon → Auto-Pinned
**Decision:** `icon != null` implies `pinned = true`. Legacy `pinned=true` without icon gets default red 📍.
**Rationale:** Single source of truth — icon presence drives pin state, not a separate boolean.
**Source:** [`UserMarker.kt`](app/src/main/java/ykws/android/maro/data/model/markers/UserMarker.kt), [`MarkersViewModel.kt:520`](app/src/main/java/ykws/android/maro/ui/map/MarkersViewModel.kt:520)

## Match Resolution

### On-Demand Only
**Decision:** No continuous 1Hz pipeline. Match triggered by boat marker tap (CenterMarkerOverlay clickable).
**Rationale:** User-triggered, <500ms acceptable. No real-time performance constraint.
**Source:** [`MarkersViewModel.kt:654-670`](app/src/main/java/ykws/android/maro/ui/map/MarkersViewModel.kt:654)

### WhereAmIMatch Sealed Class
**Decision:** Two variants: `ZoneMatch` (boat inside geometry, purely geometric) and `ProximityMatch` (boat outside, sea-path distance to closest unblocked boundary point). Immutable `children: List<WhereAmIMatch>` for containment tree.
**Rationale:** Zone match skips land check — if boat is inside the circle/corridor it always matches. Proximity is land-gated.
**Source:** [`MarkerMatcher.kt`](app/src/main/java/ykws/android/maro/spatial/MarkerMatcher.kt)

### Depth-First Leaves-First Traversal
**Decision:** `depthFirstLeavesFirst()` sorts by `sizeOf()` (zone radius or sea distance), children before parents. Capped at 8 results.
**Rationale:** "Smallest first" — most specific match displayed first, containment tree flattened.
**Source:** [`MarkerMatcher.kt`](app/src/main/java/ykws/android/maro/spatial/MarkerMatcher.kt)

### 1km Search Fence
**Decision:** BBox pre-filter uses 1km search radius. Markers inside the fence use their full natural proximity range (no cap).
**Rationale:** 1km is a reasonable on-water visibility radius; markers beyond 1km are unlikely to be relevant.
**Source:** [`MarkerMatcher.kt`](app/src/main/java/ykws/android/maro/spatial/MarkerMatcher.kt)

## Land-Blocking Engine

### Tangent-Guided Angular Shadow Projection
**Decision:** `closestUnblockedPoint()` iterates view cones, computes angular shadows from coastline segments, merges overlapping shadows, returns closest boundary point in unblocked intervals. 10m grazing tolerance.
**Rationale:** Replaced brute-force 36-point sampling with analytical cone coverage. CoastlineSpatialIndex provides grid-pre-filtered segment queries.
**Source:** [`MarkerMatcher.kt`](app/src/main/java/ykws/android/maro/spatial/MarkerMatcher.kt), [`CoastlineSpatialIndex.kt`](app/src/main/java/ykws/android/maro/spatial/CoastlineSpatialIndex.kt)

**Known issue:** Angular shadows from wide island-spanning coastline segments merge to cover full cone, producing ~50% match rate on Sainte Marguerite corridor. Direct line test confirms closest boundary point is reachable.
**Source:** [`FEAT_HYD_Markers.md`](xTrack/Markers/FEAT_HYD_Markers.md)

### CoastlineSpatialIndex Integration
**Decision:** Reuse existing `CoastlineSpatialIndex` (500m grid cells, 0.03ms queries). Added `segmentIntersectsLand(a, b): Boolean` and `segmentsInBbox()` method. CoastlineRepository exposes `spatialIndex`.
**Rationale:** No second index build. Grid-pre-filtered segment queries with 10m grazing tolerance, short-circuits on first land hit.
**Source:** [`CoastlineSpatialIndex.kt`](app/src/main/java/ykws/android/maro/spatial/CoastlineSpatialIndex.kt)

## UI Architecture

### Wizard Creation Flow
**Decision:** Step-by-step wizard (`WizardStep` sealed class) replaces single-form `CreationContent`/`EditContent`. Steps: TypeSelect → Position → [PositionP2] → [Radius] → Proximity → Title → Description. Replaces dashboard panel during creation/editing.
**Rationale:** Single scrollable form was crowded and overwhelming. Each step presents one decision. Map stays draggable during position steps.
**Source:** [`MarkersViewModel.kt:63-71`](app/src/main/java/ykws/android/maro/ui/map/MarkersViewModel.kt:63), [`WizardDrawer.kt`](app/src/main/java/ykws/android/maro/ui/map/WizardDrawer.kt)

### Wizard Button Style
**Decision:** Text pills (`RoundedCornerShape(8.dp)`, accent background, bold white text) instead of circle icon buttons. Dimmed at 40% alpha when disabled. `AnimatedContent` slide transitions between steps.
**Rationale:** Text labels are clearer than icon-only buttons. Consistent with Settings page button style.
**Source:** [`WizardButtonRow.kt`](app/src/main/java/ykws/android/maro/ui/markers/wizard/WizardButtonRow.kt)

### Keyboard Handling
**Decision:** Toggle `windowSoftInputMode` at runtime: `adjustNothing` on text steps, restore `adjustPan` on exit. Wizard panel shifts up by `imeHeight` in portrait.
**Rationale:** Manifest-level `adjustNothing` would break Settings/Track rename fields. Runtime toggle scoped to wizard lifecycle.
**Source:** [`WizardDrawer.kt:80-91`](app/src/main/java/ykws/android/maro/ui/map/WizardDrawer.kt:80)

### Tri-State Layer Toggle
**Decision:** `MarkerLayerState` enum (HIDDEN → SHOW_ALL → SHOW_PINNED → HIDDEN) replaces binary `userMarkersVisible: Boolean`. Persisted via SettingsManager v2→v3 migration.
**Rationale:** SHOW_PINNED mode filters to pinned markers only, showing grey dashed zones for non-pinned context.
**Source:** [`MarkersViewModel.kt:53`](app/src/main/java/ykws/android/maro/ui/map/MarkersViewModel.kt:53), [`MarkerOverlay.kt:168-170`](app/src/main/java/ykws/android/maro/ui/map/MarkerOverlay.kt:168)

### Drawer Separation
**Decision:** `MarkerDrawer` handles Viewing + MatchResult only. `WizardDrawer` handles Creating + Editing (replaces dashboard). `OverlayLayer` provides animation/shadow via `DrawerSlot`.
**Rationale:** Separation of concerns — wizard replaces dashboard area, marker drawer overlays map. No more monolithic CreationContent/EditContent.
**Source:** [`MarkerDrawer.kt:101-105`](app/src/main/java/ykws/android/maro/ui/map/MarkerDrawer.kt:101), [`WizardDrawer.kt`](app/src/main/java/ykws/android/maro/ui/map/WizardDrawer.kt)

## Overlay Rendering

### OSMdroid Native Overlays
**Decision:** Pin → `Marker` with filled-circle `BitmapDrawable`. Circle → `Polygon` fill + `Polyline` outline + center `Marker`. Corridor → `Polygon` fill + two parallel `Polyline`s + centerline `Polyline` (50% alpha) + semi-circle caps + p1/p2 `Marker`s.
**Rationale:** OSMdroid overlays render natively on the MapView OpenGL surface — no Compose interop overhead.
**Source:** [`MarkerOverlay.kt`](app/src/main/java/ykws/android/maro/ui/map/MarkerOverlay.kt)

### Semi-Circle Corridor Caps
**Decision:** `addSemiCircleCaps()` draws 18-point arc polylines at p1 and p2, connecting the left and right parallel edges into a pill/racetrack shape. Fill polygon also traces the pill outline.
**Rationale:** Open parallel lines looked incomplete. Caps close the corridor band visually.
**Source:** [`MarkerOverlay.kt:623-653`](app/src/main/java/ykws/android/maro/ui/map/MarkerOverlay.kt:623)

### Area-Based Marker Tap
**Decision:** `MapEventsOverlay` with `singleTapConfirmedHelper` → hit-tests all confirmed markers within proximity zone via `closestPointOnGeometry()`. Returns list of tapped IDs (supports overlapping markers).
**Rationale:** Pin dots (6dp) are too small to hit on a moving boat. Proximity-zone tap area is generous and consistent with match logic.
**Source:** [`MarkerOverlay.kt:334-358`](app/src/main/java/ykws/android/maro/ui/map/MarkerOverlay.kt:334)

### Match Result Highlighting
**Decision:** When `matchResult != null`, matched markers render brighter/thicker (1.67× stroke), non-matched dim to 30% alpha. Selected marker gets 2.5× stroke pulse.
**Rationale:** Spatial context for "Where am I?" results — user sees which markers matched on the map.
**Source:** [`MarkerOverlay.kt:126-166`](app/src/main/java/ykws/android/maro/ui/map/MarkerOverlay.kt:126)

### Icon Rendering on Map
**Decision:** Pinned markers render POI emoji icons at their geometry positions. Pin=1 icon, Circle=center, Corridor=p1+midpoint+p2 (3 icons). `SHOW_PINNED` mode hides non-pinned geometry.
**Rationale:** Visual identification without labels. Fixed 20sp size, no zoom scaling.
**Source:** [`MarkerOverlay.kt:298-331`](app/src/main/java/ykws/android/maro/ui/map/MarkerOverlay.kt:298)

## Persistence

### JSON File Storage
**Decision:** Single `user_markers.json` in internal storage. Loaded at startup, written on every create/edit/delete. No protobuf, no export/import.
**Rationale:** 15-20 markers max — JSON is simple and debuggable. Device-local only.
**Source:** [`UserMarkerRepository.kt`](app/src/main/java/ykws/android/maro/data/markers/UserMarkerRepository.kt)

### Soft-Delete with Undo
**Decision:** Management page uses `pendingDeletes` set for soft-delete. Swipe → snackbar with Undo. Commit on panel close or snackbar swipe.
**Rationale:** Same paradigm as track list — consistent UX across the app.
**Source:** [`MarkersViewModel.kt:592-617`](app/src/main/java/ykws/android/maro/ui/map/MarkersViewModel.kt:592)

## Debug Infrastructure

### WIA Debug Mode
**Decision:** Long-press boat marker → debug mode ON → map tap runs `debugResolveAllMarkers()` with structured `Log.d("WIA", ...)` trace. Output via `adb logcat -s WIA`.
**Rationale:** Non-invasive diagnostic instrumentation. No persistent setting, no UI overlay.
